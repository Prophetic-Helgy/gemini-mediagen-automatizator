# Генерация в gemini.google.com через залогиненный Chrome (без API-ключа)

Генерация картинок (web-модель Nano Banana; по запросу на особо высокое качество —
пересоздание в Nano Banana Pro, СМ. «Пересоздание в Pro»), видео и музыки режимами
выбора («Изображения / Видео / Музыка») в web-интерфейсе gemini.google.com на
подписке пользователя, без API-ключа (подписка кредиты API не даёт — API-бэкенд не
выдумывать).
Движок — публичный пакет `browser-harness` (pip): CLI читает python-скрипт из
stdin, хелперы уже импортированы:
`list_tabs switch_tab new_tab js cdp click_at_xy page_info wait_for_load`.

Референс-реализация в этом репозитории: `examples/gen_frames.py` (батч картинок:
кадр-рецепт, префлайт и гарант аккаунта, переключение, ожидание лимита,
валидация, реестр, идемпотентность). Если скрипт нужен «как есть» — берите его, а
не переписывайте с нуля; режимы Видео/Музыка — по аналогии (СМ. «Режимы» и
«Видео с референс-фото»). UI Gemini плавает неделя за неделей — даты в тексте
указывают, когда конкретный приём был проверен живьём; перед батчем сверяйтесь
с «Типовыми граблями».

## Аккаунт (жёсткая привязка к НАСТРОЕННОМУ)

Единственный разрешённый аккаунт — тот, что настроен как `ACCOUNT`
(в `examples/gen_frames.py`; при работе «через агента» — спросите у пользователя
один раз и запоминайте в контекст/память). Правила:

- **Отдельное окно под ACCOUNT (строго, проверено 2026-09-17):** вся автоматизация
  идёт ТОЛЬКО в собственном окне, созданном под целевой профиль:
  `cdp("Target.createTarget", url="https://gemini.google.com/u/N/<вход>", newWindow=True)`
  (префикс `/u/N` — по скану аккаунта; без `newWindow` вкладка откроется в основном
  окне пользователя — так делать нельзя). Вкладки основного окна пользователя —
  ЗАПРЕЩЕНЫ: не открывать в нём вкладок, не навигировать их, не активировать
  (даже «безобидные» чтения сбивают пользователя). Своё окно по завершении —
  `cdp("Target.closeTarget", targetId=…)`.
- Перед генерацией проверить, что активный аккаунт на gemini.google.com — именно
  ACCOUNT: искомать адрес профиля в DOM (атрибуты avatar/profile-элемента,
  `aria-label`, `title`, textContent; заодно `<img>` аватара с `title`/`src`).
  Надёжнее всего — `aria-label` родителя аватара («Аккаунт Google: NAME (e-mail)»).
- Активный аккаунт — ДРУГОЙ из уже залогиненных на машине — РАЗРЕШЕНО
  переключиться самостоятельно: `location.assign`
  `https://accounts.google.com/AccountChooser?continue=https%3A%2F%2Fgemini.google.com%2Fapp`,
  в chooser найти строку с точным текстом `ACCOUNT` (shadow-piercing обход,
  точное совпадение e-mail'а, не подстрока чужого). Строка chooser НЕ реагирует на
  trusted-клик и на клик по leaf — работает ТОЛЬКО JS `.click()` по предку
  `div[role=link]` (проверено 2026-09-15); дождаться возвращения на gemini/app и
  ПОВТОРИТЬ скан.
- **«Аккаунт-гарант» в батче** (проверено 2026-09-16, каскадный провал батча):
  скан аккаунта — ПЕРЕД КАЖДЫМ кадром (внутри кадра, сразу после навигации на
  лендинг), а не один раз на старте, и ПОСЛЕ любого переключения. Вкладка может
  МОЛЧА смениться на чужой аккаунт посреди батча без всякой навигации со стороны
  кода (Google ретегит дефолтный аккаунт сам) — однократный ensure на старте не
  спасает, весь батч падает каскадом `send_failed`/`timeout_or_no_media`.
  Гарант перед отправкой в каждом кадре: скан e-mail; нет нужного → AccountChooser
  + JS-клик по `div[role=link]` → ждать возврата на gemini + повторный скан →
  иначе `fail("account_mismatch")`. После такого гаранта одиночный `send_failed` —
  это лаг UI: его надо ретраять, а не бросать карточку.
  Вкладка нужного аккаунта может быть закрыта человеком — оставшиеся вкладки
  gemini окажутся на чужих аккаунтах, и молча «наследовать первую вкладку» нельзя;
  идти через AccountChooser способом выше.
- **Многоаккаунтный URL `/u/N` (грабля 2026-09-15):** переключение сажает на
  `gemini.google.com/u/N/app`; последующие `location.assign('…/app')` (без `/u/N`)
  ОТКАТЫВАЮТ на u/0 — чужой аккаунт, и вся генерация идёт не там. Всегда
  сохраняйте префикс `/u/N` из текущего URL вкладки
  (`re.search(r"/u/\d+", url)`) и стройте навигацию с ним. После переключения —
  ПОВТОРИТЬ скан и сверять `/u/N`.
- **Сам `/u/N` — НЕ признак аккаунта (грабля 2026-09-15 вечер):** индексы
  плавают при смене зеркала/канала доступа — один и тот же `/u/N` до и после
  смены показывал разные аккаунты, а ACCOUNT переезжал на другой индекс.
  Истинная сверка — только e-mail из aria-label аватара (родитель
  `IMG`-аватара с «Аккаунт Google: … (e-mail)»); при нескольких вкладках gemini
  брать ту, где скан даёт ACCOUNT.
- Иначе переключение запрещено: НЕ вводить пароль/коды за пользователя, НЕ
  выбирать иной аккаунт, НЕ «пробовать другой». После переключения скан снова не
  ACCOUNT, либо Google требует учётные данные (`login_wall`), либо e-mail не найден
  среди залогиненных — статус `account_mismatch` / `login_wall`: ОСТАНОВКА и доклад.

## Предусловия (проверять первыми)

1. `pip install browser-harness` установлен (`browser-harness --version`;
   FileNotFound → доложить; установка/подключение Chrome — install.md в
   github.com/browser-use/browser-harness).
2. В Chrome есть вкладка/сессия gemini.google.com, залогиненная на ACCOUNT
   (см. «Аккаунт»). Логин за пользователя не выполняется НИКОГДА.
3. Один кадр ≈ 90+ с. Дневной лимит подписки реален: темп ≥90 с + джиттер между
   кадрами. Маркеры: «вы достигли лимита», «вернитесь завтра»,
   «come back tomorrow», «reached your limit» … По маркеру — СМ. «Сброс лимита».
4. Ожидание кадра, лимиты таймаутов — щедрее, чем кажется: генерация видео/музыки
   занимает минуты.

## Рецепт кадра (отлажено на живом UI 2026-09; порядок и задержки — часть рецепта)

Весь кадр — ОДИН python-скрипт в stdin `browser-harness`, печатает
`###JSON###<json>` в конце.

1. **Чистый диалог**: использовать СВОЁ отдельное окно (СМ. «Аккаунт»;
   `Target.createTarget` с `newWindow=True` — не `new_tab` в основном окне);
   `location.assign('…/app')` (с сохранённым `/u/N`, СМ. «Аккаунт») — свежий
   лендинг, чтобы «появился img» означало НАШ кадр. Внимание: лендинг стартует
   в режиме «Изображения» (чип у композера, placeholder «Опишите изображение»);
   если нужный режим уже активен — цикл выбора режима ПРОПУСКАТЬ (продавливание
   режима через «+»-меню в этом состоянии ломает отправку).
2. **Композер**: DOM-поллинг селектора `.ql-editor, div[contenteditable="true"][role="textbox"], textarea`
   до 90 с. Никаких фиксированных sleep-ов на ожидание. Берите ПОСЛЕДНИЙ ВИДИМЫЙ
   редактор (rect w/h > 0), не `querySelector`-первый: после чата в DOM остаётся
   невидимый `.ql-editor`.
3. **Режим (Изображения / Видео / Музыка)**: оверлей «Загрузка и инструменты»
   открывается JS-ом `el.click()` по кнопке (`aria-label` ~ /загрузка и инструмент/i).
   **Названия пунктов плавают от дня к дню: 2026-09-14 — «Изображения», «Видео»,
   «Музыка»; вечер 2026-09-15 — «Создание изображений», «Создание видео»,
   «Создание музыки» (DOM `.gem-menu-item-label`). Точный поиск по старому имени
   не находит пункт → режим не выбран → промпт уходит в режим по умолчанию и
   генерируется ФОТО вместо видео. Матчить ПОДСТРОКОЙ (нормализовать
   регистр/пробелы): `/создание\s+видео/i`, `/создание\s+изображений/i`
   (родительный падеж! точный `^изображения$` не матчит).**
   **Меню раскрывается ДВУМЯ волнами: сразу только «Загрузить файлы»/«Добавить с
   Google Диска»/«Другие варианты ›»; секция режимов дорисовывается асинхронно
   через 5–20 с — поллить текст нужного пункта, не кликать раньше (промах =
   дефолтный режим = фото вместо видео).** Пункт «Воплощайте идеи в жизнь» — это
   подпись (description) пункта «Создание видео», в DOM может лежать скрытой.
   **Пункт на лендинге может быть `disabled=true` (проверено 2026-09-17; внутри
   открытого чата — enabled): проверяйте `button.disabled`/`aria-disabled` — это
   не баг клика. Для видео в этом случае вести генерацию на
   `https://gemini.google.com/videos` — там режим предвыбран (чип «Видео», «+» с
   загрузкой файлов, placeholder «Опишите видео»).**
   **Надёжнее входа в видео-режим — сайдбар-пункт «Видео»: стабильный селектор
   `[data-test-id="videos-side-nav-entry-button"]` (href /videos, прямой URL
   `…/u/N/videos`) — страница «Создание видео» с галереей шаблонов и УЖЕ активным
   режимом видео + выбор соотношения сторон (16:9); шаблоны трогать не нужно —
   печатать промпт и слать.**
   Поэтому: дамп пунктов открытого оверлея (shadow-piercing: `querySelectorAll('*')`
   + рекурсия в `shadowRoot`), матч подстрогом. Открытие оверлея — JS `.click()`
   по кнопке. Выбор пункта — клик по leaf с подъёмом к НЕAREST `BUTTON` или
   role~menuitem|option (через `getRootNode().host` для shadow-границ,
   проверено 2026-09-17): хендлер живёт на `button.mat-mdc-list-item
   [role=menuitemcheckbox]` (custom-тег toolbox-drawer-item), а подъём по регулярке
   классов стопорится на `span.mdc-list-item__content` (класс содержит подстроку
   «list-item») и кликает span — без эффекта. Если JS-клик не реагирует — trusted
   `click_at_xy` по координатам пункта. Верификация — чип выбранного режима **у
   композера** (нижняя половина экрана, x>250 — иначе ловится одноимённый пункт
   боковой навигации; для видео надёжнее критерий «есть кнопка «Загрузить файл»»),
   либо placeholder («Опишите видео»). Фолбэк (путь B): trusted-клик `click_at_xy`
   по кнопке + стрелки/Enter. Между путями — `location.assign('…/app')` (сброс
   состояния меню). 3 ретрая; после неудачи — скрин-дебаг и `mode_not_selected`.
   Каждый цикл: `Page.bringToFront` + Escape-сброс (оверлей Angular закрывается
   при blur).
4. **Промпт**: клик в композер, `Input.insertText`, ВЕРИФИКАЦИЯ textContent ==
   промпт (`prompt_mismatch` иначе). Промпт = описание + «Ракурс: X» + стилевой
   блок; для картинок ещё «квадрат 1:1, ≥1024²» (для видео/музыки —
   длительность/формат по брифу). Если insertText не принимается и печатаете
   посимвольно: `keyDown` БЕЗ `text` → `char(text=ch)` → `keyUp` — `keyDown` С
   `text=` И `char` С `text=` вставляют символ ДВАЖДЫ («ооееннииее»); очистка —
   реальные CDP Ctrl+A (`modifiers=2`) + Delete, JS selectAllChildren Quill не
   признаёт; после Ctrl+A НЕ кликать (снимает выделение). Trusted-клик по
   лендинговому композеру иногда не даёт фокус (страница домонтировалась после
   замера rect): проба клик → очистить → напечатать «т» → проверить приём, до 6
   перекликов; `focus_no_accept` честнее ложного send.
5. **Отправка**: в режиме картинок Enter вставляет перевод строки, а НЕ
   отправляет — Enter НЕ жаловать НИКОГДА (фолбэк «подождать и нажать Enter»
   сжигает промпт переводом строки). Кнопка «Отправить сообщение» в режиме
   картинок принимает JS-клик **с задержкой 30–90 с** (проверено 2026-09-15):
   PRIMARY — JS `.click()` по кнопке с trimmed `aria-label`, НАЧИНАЮЩИМСЯ с
   «Отправить»/«Send» (/^(отправить|send)/i; НЕ мягкий /отправ|send/i — ловит
   декоев, СМ. реестр) (`scrollIntoView` + `.click()`; trusted-клик по её
   координатам НЕ работает), поллить принятие до **150 с, повторный `.click()`
   раз в ~12 с**; за 150 с не ушла — `send_failed` со скрин-дебагом.
   **SYNC WAIT перед ПЕРВЫМ кликом (2026-09-18): JS-клик сразу (≤2 с) после
   `insertText` отправляет ПУСТО — Quill/Angular-модель догоняет DOM за ~7 с,
   а клик по «пустой» кнопке создаёт ПУСТЫЕ чаты (без user-query). Перед
   первым кликом — пауза ~8–9 с и повторная сверка текста промпта в редакторе.**
   **Универсальный критерий принятия** (с референсами URL может НЕ меняться, а
   бабл пользователя — это `.ql-editor` с текстом промпта, поэтому «редактор
   опустел» врёт): последний ВИДИМЫЙ композер пуст ИЛИ появился
   `response-container`/стоп-кнопка ИЛИ URL стал `/app/<id>`. «Наш бабл»
   проверять только УНИКАЛЬНЫМ сегментом промпта (бойлерплейт-ловушка: все клипы
   одной серии начинаются одинаково, префикс в 30 зн. матчит чужие чаты). Для
   видео хэш чата брать сайдбар-дифом: снять `a[href*="/app/"]` (hash+title) ДО
   отправки, после — первый отсутствовавший хэш; НО если в профиле параллельно
   работает другая автоматизация/пользователь — сам дифф не доказательство,
   каждый новый хэш проверять ОТКРЫТИЕМ чата: в `user-query` («Ваш запрос …»)
   должен быть уникальный сегмент нашего промпта. Trusted-клик по координатам
   отправки — фолбэк ОСТОРОЖНО: в UI 2026-09-17/18 он чистил композер без
   создания чата (иллюзия «sent»); Enter запрещён. Регекспсы без `\b` (кириллица
   не `\w` в JS без unicode-флага).
6. **Ожидание**: картинки — DOM-поллинг `img` class~`image`, `complete`,
   `naturalWidth ≥ 512`,-src принимает и `blob:`, и `https:` (готовые картинки
   теперь `https://lh3.googleusercontent.com/gg-dl/...`); видео — `video` с
   `readyState ≥ 2`, `videoWidth > 0` и финальным `duration` (элемент виден и из
   главного документа). Скорость серверной очереди плавно меняется по дням: днём
   текст-без-референсов — 36 с, тем же вечером — >10 мин и не готова к 610 с.
   Таймаут ожидания ≥30 мин; карточка «Создание видео…» + «Вернитесь позже» при
   пустом «Ответ Gemini» = задача ЖИВАЯ (пустой ответ — норма для видео), ждать и
   НЕ перегенерировать; перед вердиктом `timeout_or_no_media` перечитать чат
   (один `location.reload` допустим, генерация идёт серверно); музыка — `audio`
   с ненулевым `duration`. Параллельно проверка текстов лимита.
7. **Выгрузка**: CSP режет fetch blob, кнопка «Скачать» — в скрытом overflow ⇒
   ПРОВЕРЕНО 2026-09-14: «Скачать изображение в полном размере» и «Ещё»→«Скачать»
   из автоматизации НЕ забираются (fetch(blob:) блокирует CSP; клик по скачиванию —
   JS и trusted — файл не создаёт; переоткрытие чата не помогает). Тупик — сразу
   canvas:
   картинка: canvas `drawImage(img)` + `toDataURL('image/png')` → base64 → файл;
   если изображение уже `https://lh3.googleusercontent.com/gg-dl/...`, а не blob —
   на странице чата canvas tainted и fetch режет CSP: фолбэк — `location.assign`
   в сам URL картинки (топ-левел навигацию CSP не режет), там same-origin canvas
   чистый → toDataURL → возврат на /app.
   видео/музыка: `video.currentSrc` — https `contribution.usercontent.google.com/download?...`
   (генерация по тексту) или `blob:` (с референсами). Для https-URL PRIMARY:
   `fetch(url, {credentials:'include'})` из вкладки ЧАТА (fetch БЕЗ credentials — «Failed to
   fetch»: отсутствующая авторизационная кука, а не CSP; проверено 2026-09-15) → base64
   чанками; фолбэк — `cdp('Browser.setDownloadBehavior', behavior='allow', downloadPath=…)` +
   `new_tab(currentSrc)` → оригинальный mp4 без перекодирования кладётся в downloadPath
   (проверено 2026-09-15; размеры с fetch+credentials совпадают побайтово), вкладку закрыть.
   **downloadPath обязан существовать ДО setDownloadBehavior.**
   **Одно окно:** весь кадр — доступ, промпт, отправка, ожидание и выгрузка — в ОДНОЙ вкладке
   своего отдельного окна (той, где начата генерация); `new_tab` открывает вкладку в текущем
   окне (фолбэк выгрузки через `new_tab(currentSrc)` — в том же своём окне, не в пользовательском;
   окно пользователю — только `Target.createTarget` с `newWindow=True`, СМ. «Аккаунт»).
   **Не основное окно пользователя:** не брать окно с десятками открытых страниц и не трогать
   вкладки пользователя — всё в своём отдельном окне, созданном под профиль, уже залогиненный
   на `ACCOUNT`. Скан аккаунта — ДО начала кадра.
   Для `blob:` — `fetch(blobUrl)→arrayBuffer→base64`;
   фолбэк — CDP-перехват (`Network.responseReceived` → `Network.getResponseBody`,
   base64-флаг). Чанковать base64 наружу (`window.__b64.substr(pos, 2_500_000)`
   повторным `js()`), целиком в одну печать не сувать — мост режет.
   Ролик из УЖЕ ГОТОВОГО чата (например, отправленного другим диалогом) забирается
   тем же fetch+credentials без перегенерации — экономит дневной лимит; вкладку
   чата при этом НЕ перезагружать лишний раз, поллить `video[readyState>=2]`.

## Режимы

- **Изображения** (Nano Banana / Pro): рецепт выше целиком; валидация PIL — СМ. ниже.
- **Видео / Музыка**: тот же конвейер; отличается пункт меню (шаг 3), критерий
  готовности (шаг 6) и способ выгрузки (шаг 7). Скорость видео — от секунд до >10 мин
  (серверная очередь, зависит от дня); таймаут — ≥30 мин в обоих случаях.
  В реестре `kind` = image|video|music.
- **Видео с картинками-референсами** — отдельный путь, СМ. следующий раздел.

## Видео с референс-фото (проверено живьём 2026-09-15/16 на батче серии клипов)

- **Режим «Видео»**: тот же оверлей «Загрузка и инструменты» либо `/videos`
  (название пункта плавает — СМ. шаг 3). В композере видео-режима появляются
  кнопки «Загрузить файл» и «Соотношение сторон, Горизонтальное (16:9)».
- **Прикрепление файлов**: `input[type=file]` НЕТ в DOM, пока не кликнешь
  «Загрузить файл», и JS `.click()` не даёт user activation (ничего не
  происходит). Порядок: `Page.setInterceptFileChooserDialog enabled=True` →
  **trusted** `click_at_xy` по кнопке → input появляется в ГЛАВНОМ документе
  (pierce-обход `DOM.getDocument`) → `DOM.setFileInputFiles(files=[абс. пути],
  backendNodeId=...)` → чипы = `IMG/VIDEO` с `blob:` src.
  `Page.handleFileChooser` в Chrome УДАЛЁН (-32601) — не искать. Оверлей «+»
  («Файлы») в видео-режиме input'ов НЕ даёт — только «Загрузить файл».
- **Критерий отправки с референсами**: СМ. шаг 5 (URL может не меняться;
  «редактор опустел» врёт).
- **Veo с картинками идёт через пред-фазу «Выполняю анализ»** (анализ
  референсов) — 8–9-сек клип может готовиться >20 мин от отправки. Таймаут
  ожидания щедрый (25+ мин); по таймауту НЕ повторять отправку — чат живёт,
  video появится позже: отдельный recovery-цикл (поллинг `<video>` в этой же
  вкладке, без навигации) + та же чанковая выгрузка.
- **Возрастные формулировки**: Veo отказывает («Я не могу создать это видео») на
  законном промпте, если «молодой человек» читается как несовершеннолетний —
  писать «зрелый мужчина/женщина»; отказ НЕ создаёт видео в чате (чат dead) — не
  пересылать тот же промпт циклом.
- **Выгрузка**: `blob:` src — fetch из страницы работает (в отличие от картинок),
  b64 чанковать по ~2.5 МБ повторным `js()`. При
  `https://contribution.usercontent.google.com/download?...` — PRIMARY
  fetch+credentials из вкладки чата, фолбэк download_tab.

## Пересоздание в Pro (по запросу «особо высокое качество», проверено 2026-09-14)

Обычная генерация идёт Nano Banana (режим «Изображения»). Более качественный вариант
— **Nano Banana Pro** — доступен НЕ в меню «+», а на уже созданном изображении, как
наслоение на обычное создание:

- В тулбаре сообщения-картинки (ряд действий под изображением) — кнопка «Ещё»:
  `data-test-id="more-menu-button"`, `aria-label` ~ /показать другие варианты/i,
  тултип «Ещё». В композере/меню «+» Pro нет.
- Клик по «Ещё» (js `.click()` по `<button>`, shadow-piercing обход) → меню с
  пунктами; нужен «Пересоздать в Pro» (текст искать /пересоздать в pro|recreate in
  pro/i, leaf + клик предку `[role=menuitem]`/`gem-menu-item`; меню может
  прокручиваться — листать при промахе).
- Соседняя кнопка «Повторить» (`data-test-id="regenerate-button"`) — обычное
  пересоздание: новый ВАРИАНТ того же режима (счётчик «2/2», «3/3» у тулбара).
  Pro-пункт создаёт вариант в Pro (детальнее по микрофактуре; на web разрешение
  1024², как у обычной).
- Ожидание: поллинг НОВОГО `img` (blob-URL отличается от прежних, `naturalWidth ≥
  512`); индикатор «генерации» может висеть и после готовности — не доверять.
  В реестр — отдельный ряд (name с суффиксом `_pro`). На Pro-пересоздание
  распространяется суточный лимит.

## Валидация кадра (для картинок — PIL, не «на глаз»)

- размер ≥ целевого (обычно 1024²);
- однотонный фон: разброс RGB 4 углов ≤ 30;
- объект по центру: bbox ненулевых пикселей (Δ>60 от фона) в ±0.16 от центра;
- доля объекта 4–95 % (мелкий/съевшийся кадр — реджект).

Провал → ретрай с **переразметкой** промпта (прогрессивно жёстче: «фон строго
однотонный, объект один, крупно, по центре, без теней и текста»), ≤3 попыток,
дальше `needs_human_review`. Принятый кадр на диске — идемпотентность: не
перегенерировать.

## Сброс лимита: ждать и продолжать

По маркеру лимита Gemini печатает сообщение со **датой и временем сброса**. Это не
конец очереди: распарсить, дождаться, продолжать.

- **Коррекция времени**: UI может показывать время сброса в поясе, отличном от
  системного. По умолчанию поправка НЕ применяется (OFFSET=0); проверьте смещение
  ОДИН раз по первому сообщению о лимите и, если оно ненулевое, зафиксируйте.
- **Дата** может быть другим днём («15 сентября», «Sep 15», «15.09») — брать её.
  Даты нет → сегодня; если после коррекции момент прошёл → завтра.
- Ждать до (скорректированный момент **+ 2 минуты** «для верности»), спать чанками
  с логом, затем ПРОДОЛЖИТЬ очередь с того же кадра (ретраям лимит не засчитывать;
  в реестр — строка `fail:limit_reached` с исходным текстом сообщения).
- Парсить из окна текста вокруг маркера: время `(\d{1,2}):(\d{2})`, дата — `дд.мм`
  или «число + месяц (род. падеж)». Время не нашлось → ОСТАНОВКА и доклад (не
  гадать). Ожидание > 26 ч → `needs_human_review`.

## Реестр (обязательно)

CSV-ряд на каждый кадр (успех И провал): kind, name, frame, **точный промпт**,
модель, UTC, файл, sha256, статус (`ok`/`fail:…`/`needs_human_review`),
длительность. Без реестра батч не воспроизводим. Внимание: реестр хранит промпты
— не допускайте в них персональных данных, если реестр куда-то коммитится.

| Довериться trusted-клику «+»/↓↓↓→Enter | UI с 2026-09 плоский, JS `.click()` открывает оверлей; trusted-путь — только фолбэк |
| Enter вместо отправки печатает перенос строки | жать `.click()` по кнопке отправки (`aria-label` ~ /отправ\|send/i), не Enter |
| `mode_not_selected` после trusted-ретрая | фокус меню засорён — `location.assign('…/app')` между путями |
| Чип не виден `querySelector` | Angular shadow-DOM — рекурсия в `shadowRoot` |
| `fetch(blob)` / скачивание не работает | CSP — canvas toDataURL для картинок; для media с https-src — fetch+credentials из вкладки чата (или `Browser.setDownloadBehavior`+`new_tab`), для blob — fetch/CDP-перехват. Кнопка «Скачать в полном размере» из автоматизации НЕ срабатывает — не пытаться |
| fetch mp4 с usercontent «Failed to fetch» | не хватает авторизационной куки: `{credentials:'include'}` из вкладки чата — проходит |
| Картинка в чате есть, а кадр её «не видит» (`timeout_or_no_image`) или `canvas_export_failed` | готовое изображение теперь не `blob:`, а `https://lh3.googleusercontent.com/gg-dl/...`: фильтр img принимает `blob:` и `https:`; на странице чата canvas tainted и fetch режет CSP — фолбэк: `location.assign` в сам URL картинки (топ-левел навигацию CSP не режет), там same-origin canvas → toDataURL → возврат на /app |

Не баг клика: проверь `button.disabled`/`aria-disabled`. Генерацию видео вести на `https://gemini.google.com/videos` — там режим предвыбран |

| В видео-режиме URL не меняется на /app/<hash> | хэш чата — сайдбар-дифом: сним `a[href*="/app/"]` (hash+title) ДО отправки, после — первый новый хэш |

| Промпт в композере с удвоенными буквами («ооееннииее») | `keyDown` С `text=` И `char` С `text=` вставляют символ дважды. Набор: `keyDown` БЕЗ text → `char(text=ch)` → `keyUp`. Очистка — реальные CDP Ctrl+A(modifiers=2)+Delete; JS selectAllChildren Quill не признаёт; после Ctrl+A НЕ кликать |
| `prompt_mismatch`, have пустое (скрин: композер чист) | trusted-клик по лендинговому композеру иногда не даёт фокус (страница домонтировалась после замера rect). Проба: клик → очистить → напечатать «т» → проверить приём, иначе переклик до 6; `focus_no_accept` честнее ложного send |

| Чип режима «найден», а кнопки «Загрузить файл» нет | чип сверяется по тексту «Видео» и ловит пункт бокового меню; верификация чипа — только в нижней половине экрана (у композера), либо критерий = наличие кнопки «Загрузить файл» |

| Каскад `send_failed`/`timeout` на ровном месте посреди батча | вкладка молча сменила аккаунт (Google ретегит дефолт сам, без навигации со стороны кода) — гарант аккаунта перед КАЖДЫМ кадром, не только ensure на старте |
| `send_failed` без смены аккаунта: композер пуст, чата нет, скрин — чистый лендинг | новый лендинг СТАРТУЕТ в режиме «Изображения» (чип у композера, placeholder «Опишите изображение»); продавливание режима через «+»-меню в этом состоянии ЛОМАЕТ отправку. | На AccountChooser клик по строке аккаунта «не давит» | страница `accounts.google.com/.../accountchooser`: trusted `click_at_xy` и JS `.click()` по leaf бесполезны — работает только JS `.click()` по предку `div[role="link"]`; признак возврата — `href.startswith` с точного URL gemini (подстрока 'gemini.google.com' ложно светится в continue-параметре URL chooser'а) |
| Лимит «сбросится завтра» и очередь встала | читать дату+время из сообщения, +OFFSET, +2 мин, спать и продолжать |
| Зонд «чистый промпт найден» на префиксе 30 зн. | бойлерплейт-ловушка: все клипы серии начинаются одинаково; атрибутировать только уникальными сегментами |
| `harness_no_json` + «Unexpected end of input», python-компиляция фрейма ОК | двухъярусные кавычки: FRAME-шаблон парсится python'ом ВДВОЙНЕ, `\"\"` схлопывается в пустоту и браузер получает висячее JS-выражение. Вложенные кадры — одинарные кавычки внутри JS; перед прогоном проверь каждое js-выражение `node --check` |
| В адресной строке `…/function%20URL()%20…` и 404 после навигации | `js('location.assign(URL)')` — в ПЕЙДЖЕ `URL` это встроенный конструктор JS, а не переменная фрейма (то же с голомыми python-именами → ReferenceError, harness умирает без JSON). | Провалы с «чужим» текстом в have, странные тайминги реестра | ДВА драйвера на одном браузере: остановка bash-обёртки убивает только её, python-очередь оживает орфаном. Лечить: замок PID-файла в обёртке + kill по CommandLine процесса очереди |
