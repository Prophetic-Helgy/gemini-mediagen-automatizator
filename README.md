# gemini-imagegen-browser

**English:** [README.en.md](README.en.md)

**Skill для Claude Code** + автономный пример-скрипт: генерация **изображений
(Nano Banana Pro), видео и музыки** в web-интерфейсе **gemini.google.com** через
уже залогиненную вкладку вашего Chrome — **без API-ключа**, в рамках вашей же
подписки Google AI.

Агент (Claude Code) управляет реальным браузером через
[browser-harness](https://github.com/browser-use/browser-harness) (CDP): открывает
чистый лендинг Gemini, выбирает режим в меню «+», вставляет и верифицирует промпт,
отправляет его, дожидается готового медиа и вытаскивает файл в обход CSP
(canvas `toDataURL` / CDP-перехват сетевых ответов). Всё — тем же аккаунтом,
подписку которого вы уже оплачиваете: web-модели Gemini (Nano Banana Pro и др.)
кредитов API не имеют, и это единственный легальный способ их автоматизировать.

```
Claude Code ──(python-скрипт из stdin)──▶ browser-harness ──CDP──▶ ваш Chrome
                                                               └─ вкладка gemini.google.com (залогинена)
```

## Возможности

| | |
|---|---|
| **Что генерирует** | изображения (Nano Banana Pro), видео и музыка — три режима пикера «+» в gemini.google.com |
| **Без API-ключа** | работает на web-подписке; ключ не нужен и не заводится |
| **Пакетный режим** | очередь кадров: темп ≥90 с + джиттер (защита от суточного лимита), ретраи с «переразметкой» промпта |
| **Верификация каждого шага** | режим выбран (чип в shadow-DOM), промпт вставлен побайтно, сообщение отправлено (композер опустел), медиа готово (`naturalWidth`/`readyState`/`duration`) — ошибка приходит с диагностикой, а не «пустой файл» |
| **Валидация картинок** | PIL: размер, аспект ~1:1, «не однотон»; провал → авто-ретрай с ужесточением промпта |
| **Учёт лимитов** | при сообщении о лимите парсятся дата/время сброса, добавляется поправка на расхождение часов UI (настраивается, `OFFSET_H`), скрипт спит до сброса +2 минуты и **продолжает очередь** — не бросает батч на середине |
| **Контроль аккаунта** | префлайт находит e-mail активного профиля в DOM; генерация идёт только на заданном `ACCOUNT`; при надобности — переключение через AccountChooser строго на него (пароли не вводятся никогда) |
| **Идемпотентность и реестр** | готовые файлы не перегенерируются; CSV-реестр с рядом на каждый кадр (успех и провал): точный промпт, sha256, статус, длительность — батч воспроизводим |
| **Обход CSP** | выгрузка: canvas `toDataURL` (картинки), `fetch(blob)→base64` / CDP `Network.getResponseBody` (видео/аудио) |

## Варианты применения

- **Референс-ассеты для разработки игр/приложений**: иконки предметов, тайл-текстуры,
  фоны меню — пачкой, по одному промпту-шаблону, с реестром «что откуда».
- **Текстуры и фоны для печати/дизайна**: «мрамор/штукатурка/лен», задники
  полиграфии — квадрат 1:1 с запасом режется под формат, на A6-полосу хватает
  и 1024², но 2K пример уже держит.
- **Продуктовая «съёмка» без фотостудии**: товар на нейтральном фоне из описания.
- **Иллюстрации для статей/доков/презентаций**, когда стоки не подходят, а API — лишний расход.
- **Короткие видео и музыкальные подукладки** (режимы «Видео»/«Музыка») — тем же конвейером.
- **Автоматизация «в один запрос»**: в Claude Code достаточно попросить
  «сгенерируй N референсов X через мой Gemini» — скилл подхватит рецепт целиком.

## Требования (обязательно, «под ключ»)

1. **Подписка Google AI** (Pro/Ultra) на том аккаунте, которым генерируете.
   Кредитов API подписка не даёт — весь смысл в web-сессии.
2. **Chrome (обычный, ваш профиль), залогиненный в Google** — и **открытая
   вкладка `gemini.google.com`**, авторизованная этим аккаунтом. Скрипт ничего не
   логинов: он берёт существующую сессию. Нет вкладки — префлайт создаст её, но
   только в уже залогиненном браузере; запрос логина = остановка с докладом.
3. **browser-harness**: `pip install browser-harness` (публичный пакет,
   [browser-use/browser-harness](https://github.com/browser-use/browser-harness)).
   Он поднимает CDP-даемон к вашему Chrome; при проблемах подключения — его
   `install.md`.
4. **Claude Code** (или другой агент, читающий SKILL.md) с правом запускать
   `browser-harness` в терминале. Для Claude Code: положите `SKILL.md` в
   `~/.claude/skills/gemini-imagegen-browser/` — и скилл станет доступен по
   запросу «сгенерируй … через Gemini».
5. **Разрешения/риски, честно**:
   - Агент управляет вашим **реальным браузером с вашей сессией** — доверяйте
     только своему промпту и своему агенту; при первом запуске смотрите, что
     происходит на экране.
   - Скрипт **не вводит пароли и коды** и не трогает аккаунты, кроме заданного.
   - Суточный лимит генераций реален: кадр ≈ 1,5–4 мин; на лимите скрипт ждёт и
     продолжает (см. возможности), но гнать очередь «в упор» бессмысленно.
   - Это **автоматизация web-интерфейса**: Google может менять разметку — рецепты
     в SKILL.md отлажены под UI 2026-09-14, раздел «Типовые грабли» помогает
     чинить; автоматизация может нарушать условия использования сервиса —
     оцените это сами, прежде чем пускать её на свой аккаунт.

## Быстрый старт

```bash
pip install browser-harness
```

1. Откройте Chrome, убедитесь, что gemini.google.com открывается без логина.
2. Отредактируйте `examples/gen_frames.py`:
   - `ACCOUNT = "ваш@gmail.com"` — единственный аккаунт для генерации;
   - `OFFSET_H = 1` — на сколько часы Gemini UI отстают от системных (у разных
     часовых зон/регионов по-разному; поправится при первом же сообщении о лимите);
   - `JOBS = [(имя, промпт), …]` — очередь кадров.
3. Запустите:

```bash
python examples/gen_frames.py
```

Рядом со скриптом появятся `*.jpg` (1024², JPEG q90 ≤2000 px) и `gen_registry.csv`.
Повторный запуск досоздаёт недостающее, не трогая готовое.

### Установка скилла в Claude Code

```bash
mkdir -p ~/.claude/skills/gemini-imagegen-browser
cp SKILL.md ~/.claude/skills/gemini-imagegen-browser/SKILL.md
```

В SKILL.md нет конкретного e-mail'а: агент спросит ваш аккаунт один раз и
зафиксирует в памяти сессии/проекта.

## Как это работает внутри (кратко)

1. Префлайт: в DOM ищется e-mail активного профиля → сверка с `ACCOUNT`;
   чужой аккаунт → AccountChooser → строго свой, иначе стоп.
2. На каждый кадр: свежий `/app` (гарантия, что картинка — наша), ожидание
   композера поллингом, выбор режима JS-кликом по плоскому меню + верификация чипа
   через shadow-piercing обход, `Input.insertText` + сверка текста, отправка
   JS-кликом кнопки, поллинг готовности, выгрузка, валидация PIL, реестр.
3. Лимит: парсинг даты/времени сброса из сообщения (включая «15 сентября»,
   `дд.мм`, перенос через полночь), +`OFFSET_H` часов, сон до момента +2 мин,
   продолжение очереди.
